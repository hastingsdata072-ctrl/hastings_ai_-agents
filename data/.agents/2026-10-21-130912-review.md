# Kenya Health Facility CSV builder — full data pipeline review

The script `build_facilities_csv.py` replaces a broken pipeline that produced
40 counties, corrupted display names ("Taitataveta"), a phantom "Eldoret" county,
and counties stuck with a single "Central" sub-county. The rewrite uses bounding-box
coordinate matching for county assignment and a hardcoded but officially-sourced
sub-county roster for all 47 counties. The audit report confirms 47/47 counties
present and all named assertions passing.

**Watch for:** Laikipia has only 1 facility in the source and therefore only 1
distinct sub-county in the output; the audit flags it as suspect but no assertion
fails — confirmed gap against the task spec. Nyeri's sub-county roster contains
8 entries but one ("Kieni") is the ancestor of "Kieni East" and "Kieni West", which
are both also listed; bare "Kieni" is not a current official sub-county name.
Sub-county assignment is round-robin, not spatial — facilities are not placed in
the correct sub-county for their coordinates.

**Verdict**: CHANGES_REQUESTED

---

## High-level view

County assignment is coordinate-driven: every facility is placed by testing its
lat/lon against 47 bounding boxes, picking the smallest-area match when boxes
overlap. No string from the source CSV is ever used as a county name, which
structurally eliminates the Eldoret phantom county and corrupted display name bugs.

Sub-county assignment is round-robin per county using the pre-built roster. This
guarantees every county gets multiple sub-counties in the output as long as the
roster has ≥ 2 entries — so the "Central" sole-sub-county bug is eliminated. The
tradeoff is that individual facilities are not placed in their real sub-county;
the sub-county column reflects distribution, not geography. This is not documented
anywhere in the code.

Laikipia has only 1 facility in the source CSV, so round-robin always lands on
index 0 ("Laikipia West"). The audit flags this as a suspect county, but the
assertion in section 9 only checks for "Central" as the sole sub-county. A real
sub-county name like "Laikipia West" passes the assertion even when it is the
only sub-county — leaving a gap against the task requirement that such cases
*"fail loudly."*

Nyeri's roster carries "Kieni" alongside "Kieni East" and "Kieni West". Kenya's
2013 administrative boundaries replaced bare "Kieni" with its two sub-divisions;
the parent name is no longer a valid current sub-county. Facilities round-robined
to "Kieni" will carry an invalid label.

3. **Round-robin sub-county assignment is undocumented** — Nothing in the file
   states that `sub_county` values are distributed evenly across the roster rather
   than spatially assigned. Any downstream consumer treating the column as a
   geographic fact gets incorrect data. Add a prominent WARNING comment to
   `assign_sub_county` and to the file docstring.

4. **`CANONICAL_MAP` overstates its safety value** — The map is an identity
   mapping (every key maps to itself). The comment "map kept for safety" implies
   it corrects source mis-spellings, but county names are never read from the
   source CSV — they come from `COUNTY_BOXES` keys. Either populate it with real
   alternate spellings (e.g. `"Tana river"`, `"Muranga"`, `"Elgeyo Marakwet"`)
   so it does what the comment claims, or remove the comment to avoid false
   confidence.

### Laikipia single-sub-county (confirmed, assertion gap)

Laikipia has 1 facility in `kenya_hospitals.csv`. Round-robin on a 3-entry list
always lands on index 0 ("Laikipia West") for a single row. The audit section 6
flags: `Laikipia: only 1 distinct sub-county: ['Laikipia West']`. Section 9
does not treat this as a failure — the assertion only blocks "Central" as sole
sub-county, not any single sub-county. The task specification requires:
*"a county with fewer than 2 sub-counties — flag as suspect"* and
*"assertions that fail loudly"*; the current code flags but does not fail loudly.

### Nyeri sub-county roster inconsistency (confirmed)

`KENYA_SUB_COUNTIES["Nyeri"]` is: `["Tetu", "Kieni", "Mathira", "Nyeri Town",
"Othaya", "Mukurweini", "Kieni East", "Kieni West"]`. Kenya's 2013 devolution
divided the old Kieni constituency into Kieni East and Kieni West sub-counties.
Bare "Kieni" is not listed in the KMHFL as a current sub-county; it survives as
a constituency name. All three variants appearing in the roster means 1 in every
8 Nyeri facilities will be tagged "Kieni", an invalid current sub-county name.

### COUNTY_BOXES: 47 canonical names, no phantom entries

All 47 keys match the task's canonical list exactly. Multi-word and hyphenated
names ("Taita-Taveta", "Tana River", "Elgeyo-Marakwet", "Murang'a") are correct.
No "Eldoret" entry. The `assert len(COUNTY_BOXES) == 47` guard runs at import time.

### Kiambu and Uasin Gishu sub-county spot-check

Kiambu (12): Gatundu North, Gatundu South, Githunguri, Juja, Kabete, Kiambaa,
Kiambu, Kikuyu, Lari, Limuru, Ruiru, Thika Town — matches the 12 official
sub-counties (the sub-county named "Kiambu" inside Kiambu County is a valid
distinct administrative unit, not a naming collision).

Uasin Gishu (6): Ainabkoi, Kapseret, Kesses, Moiben, Soy, Turbo — matches the
6 official sub-counties exactly.

### Nairobi / Kiambu bounding-box overlap (likely, low severity)

Nairobi's box (`-1.45`–`-1.15` lat) overlaps Kiambu's (`-1.30`–`-0.80`) along
the northern strip. Smallest-area resolution sends overlapping facilities to Nairobi.
Facilities near Ruiru or Juja (Kiambu's southern edge at ~`-1.25`) could be
misassigned to Nairobi. This is inherent to bounding-box approaches and not a new
bug, but it means the Kiambu facility count may be under-reported by a small number.
