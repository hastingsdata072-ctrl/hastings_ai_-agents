Reflection
Design decision — loyalty discount calculation. The calculate_loyalty_discount tool needed clear, deterministic rules for points redemption, since the project brief specified capping redemption at 50% of the order value and flooring to the nearest 500 points, but didn't specify an exact points-to-dollar conversion rate. I chose a 100-points-per-dollar ratio, applied before the tier discount rather than after, so that the tier percentage always applies to the customer's true out-of-pocket remainder rather than the full list price. I deliberately ran this arithmetic inside the AgentCore Code Interpreter rather than letting the model compute it directly, since LLMs are unreliable at multi-step arithmetic with rounding and floor operations — a wrong loyalty calculation is the kind of error a real customer would notice immediately.
Challenge encountered. After deploying, two tools — the Knowledge Base search and the Browser tool — silently failed. The agent didn't error out; it apologized for a "system limitation" and fabricated a plausible-sounding answer instead, which is a genuinely dangerous failure mode in a customer-facing system. Checking CloudWatch and the runtime's IAM role revealed the auto-created execution role had permissions for Memory, Code Interpreter, and model invocation, but nothing for bedrock:Retrieve on the Knowledge Base or for starting AgentCore Browser sessions. I resolved this by attaching a scoped inline policy granting exactly those two capabilities against the specific KB and browser ARNs, then re-ran both tests successfully.
Production consideration — observability and silent failure. This same incident is the strongest production lesson from the project: a permissions gap produced a confident, wrong-sounding answer rather than a visible error. In production, I would add explicit tool-level exception logging and a monitoring alert whenever a tool call fails, rather than allowing the agent to gracefully paper over the failure in its response text — silent degradation is far more costly at scale than an obvious error, because customers and support staff have no signal that something needs fixing.
